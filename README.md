# IMC Command Center · 整合营销作战台

一个用来展示 **整合营销 Campaign 的项目管理、预算、KPI、渠道执行与风险分析** 的 Web Dashboard。

> **数据声明**：本项目为个人学习与作品集演示项目。页面内的品牌、产品、金额、达人、投放账户、人名
> **全部为程序生成的虚构数据**，不接入任何企业系统，不包含任何真实客户或业务信息。
> **前台查看与后台编辑都不需要登录**；后台改动的数据存在浏览器本地（localStorage），只对当前这个浏览器生效。

## 一、它长什么样

左侧固定导航，一共 6 个模块：

| 页面 | 路径 | 内容 |
| --- | --- | --- |
| Dashboard | `#/` | 5 张核心状态卡（总预算 / 预算使用率 / KPI 综合达成率 / 项目进度 / 风险状态）、每日花费与曝光趋势、核心 KPI 简洁列表、项目阶段、当前需要关注（最多 3 条，自动生成） |
| Campaign Overview | `#/campaign` | Campaign 档案、目标、四阶段节奏时间轴、分平台目标人群、渠道分工与合作模式 |
| Project Execution | `#/execution` | 执行总览与分渠道进度、15 项任务进度（可按阶段筛选）、8 位达人项目明细（仅小红书 / 抖音）、6 个投放账户明细 |
| Budget | `#/budget` | 总预算 / 已使用 / 剩余 / 使用率、预算分布图（各维度占比）、10 个预算维度明细、分渠道执行、超支预警与建议动作 |
| KPI | `#/kpi` | 5 项核心指标（曝光 / 点击互动 / A3 / TI / 平台搜索）达成率、差距测算、趋势判断、分渠道曝光与互动拆解 |
| Risk | `#/risk` | 4 个风险摘要指标、风险优先级概览（概率 × 影响矩阵）、**重点风险 TOP 5**、未来 10 天风险动作 |
| **Admin（后台）** | `#/admin` | 数据状态（当前 Campaign / 数据更新时间 / 已修改项）+ 5 个数据管理入口 + 恢复默认数据 |
| Admin · Campaign | `#/admin/campaign` | 名称、ID、周期、数据截止日、状态、当前阶段、目标、负责人、团队 |
| Admin · Execution | `#/admin/execution` | 任务的新增 / 编辑 / 删除（阶段、渠道、负责人、排期、完成率、状态、优先级） |
| Admin · Budget | `#/admin/budget` | 10 个维度的预算与已使用；剩余、使用率、四个合计全部自动计算 + 口径对账提示 |
| Admin · KPI | `#/admin/kpi` | 5 项指标的名称、当前值、目标值；完成率与状态自动计算 + 口径一致性提示 |
| Admin · Risk | `#/admin/risk` | 风险的新增 / 编辑 / 删除；等级按「概率 × 影响」自动判定 |

## 三、本地运行

需要先安装 [Node.js](https://nodejs.org/)（建议 20 或更高版本）。

```bash
# 1. 安装依赖（第一次需要，约 1-3 分钟）
npm install

# 2. 启动本地预览，浏览器会自动打开 http://localhost:5173
npm run dev

# 3. 停止运行：在终端按 Ctrl + C
```

其他命令：

```bash
npm run build      # 打包成静态文件，输出到 dist/
npm run preview    # 本地预览打包结果
npm run typecheck  # 只做类型检查，不打包
```


## 五、谁负责数据，谁负责页面

项目严格分成三层，**页面里不再存放任何业务数据**。

### 第 1 层：数据层 `src/data/` + `src/store/` —— 只放数据，不放逻辑

| 文件 | 负责什么 |
| --- | --- |
| `campaign.ts` | **项目数据**：Campaign 基本信息、目标、四个执行阶段、核心传播信息 |
| `channels.ts` | **渠道数据**：小红书 / 抖音 / 微信视频号 的预算、消耗、曝光、点击、互动、内容与目标，以及是否有达人合作 |
| `audiences.ts` | **人群画像数据**：分平台的人群资产标签（小红书 TI、抖音 A3 等）与画像特征 |
| `tasks.ts` | **任务进度数据**：15 项执行任务的进度与状态 |
| `kols.ts` | **达人项目数据**：8 位合作达人的报价、排期与效果（微信视频号不做达人合作） |
| `ads.ts` | **投流项目数据**：6 个付费投放账户的花费、曝光、点击与 CTR |
| `budget.ts` | **预算数据**：10 个预算维度（Dimension 01 ~ 10）的预算额与已使用额；剩余、使用率、占比全部由页面自动算 |
| `risk.ts` | **风险数据**：12 项已登记风险；⚠️ **只登记概率与影响两个输入值，不写等级** |
| `kpi.ts` | **KPI 数据**：5 项指标的目标值、权重、责任人与统计口径（曝光与点击互动的实际值由 daily 自动累加） |
| `insights.ts` | **结论与文案**：所有图表解读、结论段落、建议清单、应对节奏 |
| `daily.ts` | **每日趋势数据**：由上面数据自动推导生成，不用手写 |
| `index.ts` | 统一出口，页面统一从这里取数 |

### 第 2 层：计算层 `src/utils/` —— 只算数，不画界面

| 文件 | 负责什么 |
| --- | --- |
| `metrics.ts` | 时间进度、预算进度、阶段完成度等派生计算 |
| `kpi.ts` | 从每日数据算出 KPI 实际值、达成率、分渠道拆解 |
| `execution.ts` | 从任务/达人/投流数据算出各项执行进度 |
| `format.ts` | 金额、数字、百分比、日期的统一格式化 |
| `text.ts` | 文案占位符替换（把真实数字填进文案模板） |
| `labels.ts` | 状态到中文标签与颜色的映射 |

### 第 3 层：展示层 `src/pages/` 与 `src/components/` —— 只负责显示

| 文件 | 负责什么 |
| --- | --- |
| `pages/Dashboard.tsx` | 第 1 页：总览（只放结论，明细都在其他页面） |
| `pages/CampaignOverview.tsx` | 第 2 页：Campaign 总览 |
| `pages/ProjectExecution.tsx` | 第 3 页：项目执行 |

## 六、后台数据管理（Admin）

前台 6 个页面**不需要登录**，任何人打开网址都能看。
后台入口在左侧导航最下方 **数据管理 → 后台管理**（路径 `#/admin`）—— **同样不需要登录**。

> 这是个人作品集 Demo：没有后端、没有账号体系、不发任何网络请求。
> 后台能被访问，靠的是「知道 `#/admin` 这个地址」这道很轻的门槛，而不是权限系统。

### 它是怎么工作的

```
在后台改数据 → 点「保存」→ 写入浏览器 localStorage（统一数据源）→ 页面自动重新加载
   → 数据文件重新初始化 → 所有派生数字重算 → 前台六个页面读取到最新数据
```

数据文件（`src/data/*.ts`）的写法是「**优先读 localStorage，没有就回退到代码里的 Demo 初始数据**」：

```ts
export const tasks: TaskItem[] = load<TaskItem[]>('tasks', ...) ?? defaultTasks
```

所以**前台六个页面一行都没有改**，却都能读到后台改过的数据。

### 四条边界（重要）

1. **数据只存在你这台电脑的这个浏览器里。** 换电脑、换浏览器、或者别人打开你的线上链接，看到的仍是 Demo 初始数据
   —— 这是纯前端 Demo 的必然结果，不是 bug。
2. **保存后会自动刷新页面**（约 0.3 秒），这是为了保证全站数字一致，不会出现「一半新一半旧」。
3. **渠道口径暂不可编辑**（总预算 / 总花费 / 曝光等来自三个渠道的明细）：所以只改「预算维度」时，
   前台预算页会显示「维度口径 vs 渠道口径」的差额 —— 这是页面本来就有的对账展示，不是 bug。
4. **风险等级不能直接选**：它由「概率 × 影响」自动判定（≥15 重点 / 7~14 中等 / ≤6 一般），
   后台改这两个值、等级自动重算。

### 怎么验证改动生效

1. 打开 `#/admin/budget`，把某一行的预算改掉，点底部「保存」；
2. 页面自动刷新后，打开 `#/budget`，能看到该维度与合计都变了；
3. 刷新浏览器（F5）或关掉标签页重新打开，改动仍在（存在 localStorage）；
4. 想恢复原样：回 `#/admin`，点「恢复默认演示数据」；
5. 想验证「别人看到的是初始数据」：换一个浏览器打开同一个网址，或用无痕窗口。

## 七、想改数据？改这几个文件就够了

所有模拟数据都是 `src/data/` 下的纯文本，改完保存浏览器会自动刷新。

| 你想改什么 | 改哪个文件 |
| --- | --- |
| Campaign 名称、周期、目标、阶段 | `src/data/campaign.ts` |
| 三个渠道的预算、花费、曝光、点击、互动、是否有达人合作 | `src/data/channels.ts` |
| 人群画像、平台标签（TI / A3） | `src/data/audiences.ts` |
| 任务进度、负责人、状态 | `src/data/tasks.ts` |
| 达人报价、排期、效果 | `src/data/kols.ts` |
| 投放账户、日预算、曝光与点击 | `src/data/ads.ts` |
| 预算维度名称与金额 | `src/data/budget.ts` |
| 风险清单、概率、影响、负责人、应对措施 | `src/data/risk.ts` |
| 风险分与等级的判定阈值 | `src/utils/risk.ts` |
| KPI 目标值、权重、责任人 | `src/data/kpi.ts` |
| 图表下方的解读文字、结论、建议 | `src/data/insights.ts` |

**六条要记住的规则：**

1. **总预算、总花费、各项目标值不用手写。** 它们由 `campaign.ts` 从渠道数据自动汇总，
   只改渠道数据就会跟着变，不会出现两套数字打架。
   预算页的「预算维度」是同一笔钱的另一种切法，两套合计必须相等 ——
   `budget.ts` 里的 `budgetReconciliation` 会自动对账，页面上会显示差额（正常恒为 ¥0）。
2. **不要手改 `daily.ts`。** 每日趋势是用固定种子自动生成的，并做了回溯校准，
   保证「每天累加 = 汇总数字」。改了渠道数据，趋势会自动跟着变。
3. **`insights.ts` 的文案里 `{xxx}` 是占位符**，渲染时会被真实数字替换，所以文案和表格永远一致。
   文案里的 `**粗体**`、`!!红色!!`、`++绿色++`、`%%灰色%%` 是强调标记
   （`RichText` 组件负责渲染，所以同一段文案在卡片里和页面顶部都能正常加粗）。
4. **Dashboard 只负责结论，不负责展示全部过程。**
   第一层是「项目现在怎么样」（顶部 5 张卡），第二层是「为什么」（趋势、核心 KPI、项目阶段），
   第三层是「哪里需要关注」（由 `src/utils/attention.ts` 从现有计算结果自动挑出最多 3 条）。
   预算明细在 Budget 页、KPI 明细在 KPI 页、风险清单在 Risk 页、执行明细在 Project Execution 页 ——
   Dashboard 不重复它们，只给出跳转入口。加内容前先问：这条信息对「一眼看懂当前状态」有帮助吗？
5. **KPI 快慢是跟「时间进度」比，不是跟 100% 比。** 达成率会随时间自然增长，
   项目执行到中段时直接对照 100% 会把所有指标都判成红色。`labels.ts` 里的 `paceTone()`
   负责这个判断：领先时间进度 3pp 以上为绿色，落后 5pp 以内为橙色，再低才是红色。
6. **风险等级不手写，由风险分自动判定。** 数据文件只登记「发生概率」与「影响程度」两个输入值，
   风险分 = 概率 × 影响（满分 25）；`utils/risk.ts` 里 `RISK_HIGH_MIN / RISK_MEDIUM_MIN`
   两个常量决定分档（默认 ≥15 重点风险、7~14 中等风险、≤6 一般风险）。
   概率或影响一改，等级、优先级排序、矩阵位置全部自动重算。

> 全部数据都是程序生成的虚构数据，不接入任何企业系统、不调 API、不连数据库。
